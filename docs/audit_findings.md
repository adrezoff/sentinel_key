## AUDIT-001 — CLI игнорирует конфигурацию LLM

**Приоритет:** критичный.

**Места:**

- `src/application.py`;
- `src/ai_validation/llm_client.py`.

**Описание.** `LlmConfig.from_env()` был реализован, но production-код использовал `LlmConfig()` с hardcoded-значениями. В результате CLI `--ai-enabled` не передавал в клиент `SENTINEL_KEY_LLM_API_KEY`, `SENTINEL_KEY_LLM_ENDPOINT`, `SENTINEL_KEY_LLM_MODEL` и остальные параметры. Реальный запуск завершался ошибкой авторизации при наличии ключа в окружении.

**Исправление.** При включённом AI приложение создаёт единый `LlmConfig` через `LlmConfig.from_env()` и передаёт его как в LLM-клиент, так и в фабрику AI-задач. Явно переданный программистом `llm_config` по-прежнему имеет приоритет.

**Проверка.** Добавлен regression-тест: переменные окружения должны попадать в клиент, endpoint, модель, ключ и `prompt_version` фабрики.

## AUDIT-002 — Несогласованная версия prompt

**Приоритет:** средний.

**Описание.** `DefaultAiTaskFactory` создавался с отдельным `LlmConfig()`, а LLM-клиент мог получать другой объект конфигурации. При изменённом `prompt_version` idempotency key задачи и фактическая версия prompt могли расходиться.

**Исправление.** Клиент и фабрика используют один и тот же неизменяемый экземпляр `LlmConfig`.

**Проверка.** Добавлен regression-тест единой версии prompt.

## AUDIT-003 — Тестовый буфер логов

**Приоритет:** низкий.

**Описание.** Глобальный `_log_buffer` был объявлен дважды. Кроме того, обработчики не добавляли записи в буфер, поэтому `get_test_logs()` не отражал фактически emitted-события. В кодовой базе не найдено ни одного потребителя API (`get_test_logs`, `clear_test_logs`).

**Исправление.** Удалено дублирующее объявление, а также весь неиспользуемый API: `_log_buffer`, `get_test_logs()`, `clear_test_logs()`. Это исключает поддержание мёртвого кода. При необходимости буфера для тестов в будущем будет добавлен отдельный buffer-handler.

## AUDIT-004 — Неверный уровень ошибки логгера

**Приоритет:** низкий.

**Описание.** `ContextLogger.error()` вызывал `_log(logging.WARNING, ...)`, из-за чего ошибки фильтровались как предупреждения.

**Исправление.** Используется `logging.ERROR`.

**Проверка.** Добавлен regression-тест уровня записи.

## AUDIT-005 — Integration-покрытие сквозных сценариев

**Приоритет:** средний.

**Описание.** Обязательные сценарии из `AGENTS.md` в основном покрыты unit-тестами с fake-объектами. Недостаёт end-to-end integration-тестов с временным Git-репозиторием, merge/force-push, истечением аренды, недоступным LLM и повторным обнаружением закрытого инцидента.

**Статус.** Не начато. Следующий шаг — расширить `tests/integration/` без изменения доменных контрактов.
