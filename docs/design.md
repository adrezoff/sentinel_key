# Архитектура

Git → diff добавленных строк → RawCandidate → StaticAnalyzer → Candidate
→ локальная политика или AI_VALIDATION → IncidentManager → Incident.

LLM — дополнительная проверка после локальных детекторов. Сырые значения
кандидатов остаются в памяти; сохраняются маски и HMAC-SHA256. Исходная история
удалённого репозитория хранится в Git-зеркале, поэтому его каталог требует защиты.

Состояние строится по SHA и Commit.status. Работа хранится в SQLite как дерево
Task с корнем REPOSITORY_SCAN. Feed выдаёт задачи с арендой и повторяет их после
ошибок/истечения аренды. Финализатор ждёт терминального состояния всех детей.
Ошибка LLM после повторов даёт PARTIAL, остальные кандидаты продолжают обработку.

App последовательно вызывает planner, commit worker, AI worker и finalizer.
Внутренних asyncio.Queue между стадиями сейчас нет. Git использует async subprocess,
SQLite и статический анализ — asyncio.to_thread; LLM ограничен семафором клиента.
Размер пачки ограничивает объём работы задачи, но список коммитов собирается целиком.

Кандидаты, AI-задачи, локальные инциденты, статусы коммитов и результат фиксируются
одной транзакцией. AI-вердикт, инцидент, outbox и результат — другой атомарной
операцией с проверкой аренды. UNIQUE-ограничения обеспечивают дедупликацию.

Доставка outbox и автоматическая проверка HEAD в App не реализованы.
IncidentManager принимает still_in_head от вызывающего кода.
