# ADR 0003: зависимости проекта и основной test runner

- Статус: принято
- Дата: 2026-11-05

## Контекст

Проект использует `openai` в production-коде и `pytest`/`pytest-asyncio` для
локального запуска тестов, но не имеет воспроизводимого dependency manifest.
CI запускает `unittest discover`, из-за чего не собирает все integration-тесты.
Существующие два ADR используют одинаковый номер `0001`; их историческая
нумерация сохраняется без переименования.

## Решение

- Оформить метаданные, зависимости и pytest-конфигурацию в `pyproject.toml`.
- Использовать `hatchling` как build backend и `src`-layout для installable-пакета.
- Объявить production-зависимость `openai>=3.45,<4`.
- Объявить dev-зависимости `pytest>=9.2,<10` и `pytest-asyncio>=1.4,<2`.
- Удалить поддержку `python-dotenv`: окружение передаётся стандартным механизмом
  process environment.
- Считать `pytest` основным test runner в CI и документации; тесты при этом
  могут продолжать использовать `unittest.TestCase`.
- Real-LLM тесты запускать только вручную с `SENTINEL_KEY_LLM_API_KEY`; обычный
  CI не обращается к внешней сети.

## Последствия

- Чистое окружение воспроизводится через `pip install -e ".[dev]"`.
- `pytest` находит integration-тесты без дополнительных `__init__.py`.
- Версия `openai` ограничена проверенным диапазоном `3.45.x`.
- Новые ADR продолжают текущую нумерацию с `0003`, не меняя исторические файлы.
